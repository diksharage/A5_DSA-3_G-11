Core Pipeline Algorithms

1. Hash-Based Feature Extraction

Algorithm / Data Structure:
HashMap
Purpose:
Count occurrences of words/tokens. Each token is used as a key and its frequency is stored as the value.
Input:
Preprocessed document text.
Output:
Term frequencies mapping.
Complexity: O(N)

2. Stop-Word Filtering

Data Structure:
HashSet
Purpose:
Remove common English stop-words via O(1) membership lookup before counting.

3. Feature Optimization

Algorithm:
Custom Merge Sort
Purpose:
Reduce noise and retain dominant features by sorting the term frequencies descending.
Input:
Term frequencies array
Output:
Top 15 features
Time Complexity: O(U log U)
Space Complexity: O(U)

4. Jaccard Similarity

Formula:
J(A,B) = |A ∩ B| / |A ∪ B|
Purpose:
It measures the mathematical overlap between the optimized feature sets of two documents. The current similarity threshold determines whether a graph edge is created.
Input:
Top 15 features of two documents
Output:
Float Similarity value [0.0 - 1.0]

5. Document Graph

Data Structure:
Adjacency List (Map<Document, List<Document>>)
Vertices & Edges:
Vertex = Document. Edge = Sufficient similarity between two documents.
Purpose:
An adjacency list is used because document relationships form a sparse graph, saving memory over an N×N matrix.
Space Complexity: O(V + E)

6. Breadth-First Search (BFS)

Data Structure:
Queue (LinkedList) & Visited Set
Purpose:
Discover connected documents and connected components. BFS visits a starting document and then explores its neighboring documents level by level.
Complexity: O(V + E)

7. Depth-First Search (DFS)

Data Structure:
Recursion (Call Stack) & Visited Set
Purpose:
Graph traversal. DFS explores as far as possible along one path before backtracking.
Complexity: O(V + E)

8. Connected Components

Purpose:
Each set of mutually reachable documents forms a connected component. Each component mathematically represents a candidate document group without using machine learning.
Current Components:
0

9. Dynamic Category Identification

Mechanism:
Once a connected component is identified, features from documents inside it are aggregated. The absolute most dominant features are selected to dynamically generate a category label (e.g. Feature1 / Feature2).
Note:
Categories are strictly generated from empirical DSA feature data, NOT Machine Learning, semantics, or predefined strings.

String Matching Algorithms

The framework incorporates multiple exact string matching algorithms used during the string inspection and feature analysis phase.

1. Naive String Matching

Basic Idea:
Slides the pattern over the text one character at a time.
Time Complexity: O(N * M)

2. Knuth-Morris-Pratt (KMP)

Basic Idea:
Uses the LPS (Longest Prefix Suffix) array to avoid unnecessary character comparisons.
Time Complexity: O(N + M)
Space Complexity: O(M)

3. Z Algorithm

Basic Idea:
Uses the Z-array to identify pattern matches efficiently in linear time.
Time Complexity: O(N + M)

4. Rabin-Karp

Basic Idea:
Uses a rolling hash to compare patterns, reducing strict string comparisons unless the hashes match.
Time Complexity: Average O(N + M), Worst O(N * M)

5. Aho-Corasick

Basic Idea:
Uses a Trie/automaton with failure links for simultaneous multiple-pattern matching.
Time Complexity: O(N + M + Z)
